# micro_llm: клиент LLM для колонки

Пакет для MicroPython на VK Капсуле Мини. Ведёт диалог с языковой
моделью: собирает сообщения, отправляет их движку, хранит историю и
отдаёт текст ответа. Библиотека не знает про ASR, TTS и железо - это
задача вызывающего кода.

Версия 0.1.3. Движки: `openai` (любой OpenAI-совместимый сервис, в
агенте по умолчанию), `deepseek` (REST `api.deepseek.com`) и `fake`
(эхо, без сети).

## Что умеет

- один запрос-ответ (`ask`) и потоковый ответ (`stream`);
- сессия с контекстом: TTL, ограничение пар и символов;
- системный промпт строкой или из файла;
- движки через реестр: свой движок подключается регистрацией;
- `fake` для тестов без сети и ключей;
- разбор ошибок сервиса по HTTP-кодам;
- импорт пакета не трогает сеть и железо.

## Что нужно на колонке

- MicroPython со `ssl` и `.frozen` в `MICROPYPATH`:

  ```sh
  MICROPYPATH=/home/microp:/usr/lib/micropython:.frozen
  ```

- сеть и ключи в `/home/.env`:

  ```sh
  # deepseek
  DEEPSEEK=...
  DS_MODEL=deepseek-flash
  # openai-совместимый сервис
  OAI_LLM_API=...
  OAI_LLM_URL=https://api.openai.com/v1
  OAI_LLM_MODEL=...
  ```

  Ключ можно передать и параметром (`api_key`) или через `key_file`.

## Куда ставится

```text
/home/microp/micro_llm/     пакет
/home/.env                  ключи (OAI_LLM_* или DEEPSEEK/DS_MODEL)
/home/system.txt            системный промпт (по умолчанию)
```

После этого работает `from micro_llm import LlmClient`.

## Быстрый старт

```python
from micro_llm import LlmClient

llm = LlmClient(engine="openai",
                system_file="/home/system.txt",
                ttl_ms=600000)
llm.open(max_tokens=650)
try:
    print(llm.ask("Как дела?"))
finally:
    llm.close()
```

Без сети - движок `fake`:

```python
llm = LlmClient(engine="fake")
llm.open()
try:
    print(llm.ask("проверка"))     # эхо: проверка
finally:
    llm.close()
```

## Основные вызовы

| Вызов | Что делает |
|---|---|
| `open(model=None, **options)` | открыть движок и создать сессию |
| `ask(text)` | вопрос → ответ; история пополняется |
| `stream(text)` | генератор кусков ответа; история - после полного ответа |
| `reset()` | забыть историю, системный промпт остаётся |
| `session()` / `engine()` | доступ к сессии и движку |
| `info()` | движок, модель, пары, символы, время последнего ответа |
| `close()` | закрыть движок |

## Сессия

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `ttl_ms` | 600 000 (10 мин) | после простоя история сбрасывается |
| `max_turns` | 6 | сколько пар «вопрос - ответ» хранить |
| `max_chars` | 4 000 | предел суммарной длины истории |
| `system_chars` | 2 000 | предел длины системного промпта |

История обрезается с начала: сначала удаляются самые старые пары.
`info()` возвращает `turns`, `chars`, `last_ms`.

## Текст без переносов

Перед запросом `micro_llm` выравнивает текст в одну строку: системный
промпт, историю и вопрос. Переносы строк и табуляция заменяются
пробелом, повторные пробелы схлопываются; пунктуация не меняется.

Ответ тоже возвращается плоским: `ask()` и куски `stream()` не содержат
`\n`, в историю попадает уже выровненный текст. Файл `system.txt` на
диске при этом остаётся с переносами, читать его удобно.

```python
llm.ask("Привет\nкак дела")     # в модель уйдёт "Привет как дела"
```

## Потоковый ответ

```python
for piece in llm.stream("Расскажи коротко про Луну"):
    print(piece, end="")
```

Куски приходят по мере генерации (SSE). В историю пара попадает
только после полного ответа; если поток оборвался, история не
пополняется.

## Движки

### `deepseek` (альтернатива)

Доступен как альтернатива; по умолчанию в агенте используется `openai`.
`POST https://api.deepseek.com/chat/completions`, заголовок
`Authorization: Bearer <ключ>`.

| Параметр `open()` | По умолчанию | Смысл |
|---|---|---|
| `model` | `DS_MODEL` или `deepseek-flash` | имя модели |
| `thinking` | `false` | режим размышлений; для голоса выключен |
| `max_tokens` | 400 | предел ответа (агент ставит 650) |
| `temperature` | 0.7 | вариативность |
| `timeout` | 20 с | таймаут запроса |
| `retries` | 1 | повторы при сетевой ошибке |
| `retry_delay` | 0.5 с | пауза между повторами |
| `api_key` / `key_file` | `/home/.env` | откуда взять ключ |

Ошибки сервиса разбираются по коду: 401 - ключ не принят, 429 -
превышен лимит, 402 - недостаточно средств и т. д.

### `openai`

Любой сервис с OpenAI-совместимым `POST /chat/completions`.
В агенте это движок по умолчанию. Ключ,
адрес и модель берутся только из окружения или `/home/.env`, без
значений по умолчанию:

| Переменная | Смысл |
|---|---|
| `OAI_LLM_API` | ключ, уходит как `Authorization: Bearer ...` |
| `OAI_LLM_URL` | полный адрес с префиксом, например `https://api.openai.com/v1` |
| `OAI_LLM_MODEL` | имя модели |

`OAI_LLM_URL` должен быть полным: схема `http` или `https`, хост, при
необходимости порт и префикс пути. `/chat/completions` дописывается
сам, хвостовой `/` не мешает.

```python
llm = LlmClient(engine="openai")
llm.open(max_tokens=650)     # thinking не отправляется
try:
    print(llm.ask("Привет"))
finally:
    llm.close()
```

Если переменная не задана, URL кривой или запрос не удался, движок
возвращает текст ошибки как ответ: агент озвучит его голосом. В
историю сессии такой ответ не попадает.

### `fake`

Ответ - `эхо: <последняя реплика>`, поддерживает `stream` и
`system`. Параметр `prefix` меняет префикс. Нужен для тестов агента и
сессии без сети.

Свой движок:

```python
from micro_llm import register_engine

register_engine("myservice", MyEngine)
llm = LlmClient(engine="myservice")
```

## Системный промпт

- `system="…"` - готовый текст;
- `system_file="/home/system.txt"` - прочитать при `open()` и
  обрезать до `system_chars`.

Если задан `system`, файл не читается. В агенте промпт собирает
`build_llm()`: текст файла, имя помощника и, при `[agent] age_limit`
меньше 18, блок про детей. Клиент получает уже готовую строку.

## Ограничения

- одна сессия на клиент; для параллельных диалогов - отдельные
  клиенты;
- только текст: без инструментов, картинок и JSON-режимов;
- `ask()` блокирует вызывающий код на время запроса;
- история хранится только в памяти и теряется при перезапуске;
- при обрыве потока частичный ответ не попадает в историю;
- ответы с ошибкой (движок вернул текст и `last_error`) тоже не
  попадают в историю.

# micro_ww: ключевое слово для колонки

Пакет для MicroPython на VK Капсуле Мини. Слушает микрофон и сообщает,
когда произнесена ключевая фраза. Работает полностью локально, без
сети: детектор microWakeWord (TFLite Micro) и признаки считаются на
колонке в C.

Версия 0.1.0. Движки: `fake` (без C и модели) и `microwakeword`
(модели microWakeWord: английские `hey_jarvis` и `jarvis`, русские
`алиса`, `домовой`, `кузя`, `окей_валера`, `стив`, `умка`,
`эй_железяка`). Набор моделей — данные: их можно менять и добавлять.

Библиотека — компонент, а не приложение: она не решает, когда слушать
и что делать после срабатывания. Это делает оркестратор
(`micro_agent`): по событию останавливает прослушивание и запускает
запись вопроса для ASR.

## Что умеет

- локальная детекция без облака и без сетевых запросов;
- прослушивание микрофонов колонки (`micro_hal`) или готового PCM
  через `feed()`;
- окно вероятностей, порог и пауза после срабатывания;
- настройка порога и окна из кода поверх значений манифеста;
- движки через реестр: свой движок подключается регистрацией;
- состояния и событие с вероятностью и кадром;
- `fake`-движок для тестов без C, модели и платы;
- C-рантайм `libc_ww.so` (AArch64) с моделью и манифестом как данными.

## Что нужно на колонке

- MicroPython со `ffi` и `.frozen` в `MICROPYPATH`:

  ```sh
  MICROPYPATH=/home/microp:/usr/lib/micropython:.frozen
  ```

- `micro_hal` — только для источника с микрофона;
- `bins/libc_ww.so` (AArch64) и `models/` — для движка
  `microwakeword`; движку `fake` ничего этого не нужно;
- свободный микрофон: во время прослушивания его не должен держать
  другой процесс (ASR или `voice-agent`).

## Быстрый старт

```python
from micro_ww import WakeWord
from micro_ww.sources.mic import MicroHalMic

ww = WakeWord(
    engine="microwakeword",
    model="/home/microp/micro_ww/models/hey_jarvis.json",
    mic=lambda: MicroHalMic(source="mics"),
)
ww.start()
try:
    event = ww.listen(timeout=10.0)   # None — не дождались
    if event:
        print(event["word"], event["average"], event["time_ms"])
finally:
    ww.close()
```

`WakeWord` можно использовать как контекстный менеджер:

```python
with WakeWord(engine="microwakeword", model=".../hey_jarvis.json",
              mic=lambda: MicroHalMic()) as ww:
    event = ww.poll()      # __enter__ уже вызвал start()
```

Офлайн, без микрофона — готовый PCM:

```python
ww = WakeWord(engine="microwakeword", model=".../hey_jarvis.json")
ww.feed(pcm)        # кусок s16le, моно, 16 кГц (обычно 20 мс = 640 Б)
```

## Основные вызовы

| Вызов | Что делает |
|---|---|
| `start()` | открыть движок и микрофон, начать слушать |
| `poll()` | один шаг: прочитать окно 20 мс и обработать |
| `listen(timeout=None)` | блокирующий цикл до события или таймаута (сам вызывает `start()`) |
| `feed(pcm)` | обработать готовый PCM без источника |
| `reset()` | сбросить модель и окно, не закрывая источник |
| `stop()` | закрыть микрофон; движок остаётся открытым |
| `close()` | закрыть движок и всё остальное |
| `status()` | состояние, порог, окно, кадры, последнее событие |

Событие — словарь:

```python
{
    "detected": True,
    "word": "Hey Jarvis",   # из манифеста
    "probability": 1.0,     # вероятность последнего шага
    "average": 0.98,        # среднее по окну
    "frames": 41,           # шагов обработано
    "time_ms": 1260,        # время с начала прослушивания
}
```

## Как решается срабатывание

Движок отдаёт вероятность «это ключевое слово» на каждый шаг — обычно
раз в 10 мс (задаётся манифестом). Дальше работает скользящее окно:

- `window` — сколько последних вероятностей усредняется (по умолчанию
  из манифеста, у `hey_jarvis` — 5, это ~50 мс);
- `threshold` — порог для **среднего** по окну (у манифеста 0.97);
- срабатывание возможно, только когда окно заполнено целиком;
- после срабатывания `cooldown_ms` новые события игнорируются — чтобы
  одна фраза не дала несколько подряд.

Практика: `threshold` — это чувствительность, `window` — сколько
времени фраза должна «держаться». Больше окно — устойчивее, но
медленнее и труднее сработать; меньше — быстрее и шумнее.

## Движки

- `fake` — заданные вероятности, без C и модели: все сценарии
  проверяются на хосте;
- `microwakeword` — C-рантайм `libc_ww.so` + манифест и `.tflite`
  рядом с ним.

```python
ww = WakeWord(engine="fake",
              engine_options={"probabilities": [0.1, 0.99, 0.99],
                              "repeat": False})
```

Свой движок регистрируется так:

```python
from micro_ww import register_engine, available_engines

register_engine("myservice", MyEngine)
ww = WakeWord(engine="myservice")
print(available_engines())   # ['fake', 'microwakeword', 'myservice']
```

## Источники

`MicroHalMic` — звук с микрофонов колонки, окна по 20 мс, моно,
16 кГц:

- `source="mics"` — захват, моно сводит Pulse (по умолчанию);
- `source="speex"` — готовый моно-поток после beamforming и AGC;
- `settle_ms` — сколько выбросить после открытия (по умолчанию 300 мс
  из `micro_hal`);
- `stream=` — подменить поток в тестах.

На первом замере на плате `speex` не сработал на тестовой фразе
(уровень ниже), поэтому по умолчанию выбран `mics`.

## Настройки

| Параметр | Смысл |
|---|---|
| `engine` | имя движка, по умолчанию `fake` |
| `model` | путь к манифесту или объект `Manifest` |
| `sample_rate` | частота источника; `microwakeword` — только 16 000 |
| `threshold` | порог среднего; `None` — из манифеста |
| `window` | размер окна в шагах; `None` — из манифеста |
| `cooldown_ms` | пауза после срабатывания, по умолчанию 1000 |
| `engine_options` | параметры движка (`library`, `arena_size`, `step_ms`; у `fake` — `probabilities`, `repeat`) |
| `mic` | фабрика источника или готовый объект; `None` — только `feed()` |

Значения проверяются в `Config`: `threshold` в (0…1], `window` 1…1000,
`cooldown_ms` ≥ 0, `sample_rate` 8000…48000.

## Модели

Модель — это пара файлов в `models/`: `<имя>.json` (манифест) и
`<имя>.tflite` (сама сеть). Имя в `model` манифеста считается
относительно каталога манифеста.

| Манифест | Фраза | Язык | cutoff | окно | арена | Размер |
|---|---|---|---:|---:|---:|---:|
| `hey_jarvis.json` | Hey Jarvis | en | 0.97 | 5 | 22 860 | 52 272 Б |
| `jarvis.json` | Jarvis | en | 0.5 | 5 | 32 000 | 60 840 Б |
| `алиса.json` | алиса | ru | 0.5 | 5 | 32 000 | 60 840 Б |
| `домовой.json` | домовой | ru | 0.5 | 5 | 32 000 | 60 840 Б |
| `кузя.json` | кузя | ru | 0.5 | 5 | 32 000 | 60 840 Б |
| `окей_валера.json` | Окей Валера | ru | 0.5 | 5 | 32 000 | 60 840 Б |
| `стив.json` | Стив | ru | 0.5 | 5 | 32 000 | 60 840 Б |
| `умка.json` | умка | ru | 0.5 | 5 | 32 000 | 60 840 Б |
| `эй_железяка.json` | Эй, Железяка | ru | 0.5 | 5 | 32 000 | 60 840 Б |

`wake_word` в манифесте — только подпись: она попадает в событие и
логи, саму фразу определяет обученная сеть.

### Как сменить модель

1. Выберите манифест из таблицы, например `алиса.json`.
2. В `/home/a_settings.ini` укажите путь и пороги:

   ```ini
   [ww]
   model=/home/microp/micro_ww/models/алиса.json
   threshold=0.5
   window=5
   cooldown_ms=1000
   ```

3. Перезапустите агента:
   `/home/microp/micro_agent/init.d/S99micro_agent.sh restart`.
4. Проверьте: при старте печатается `WW threshold … window …`, в логе
   после фразы — `WAKE`, в событии `word` — подпись из манифеста.

Важно: агент **всегда** передаёт `threshold` и `window` из ini, и
умолчания в коде — `0.85` и `4`. У новых моделей в манифесте `0.5` и
`5`, поэтому при смене модели обязательно поправьте эти два ключа,
иначе она почти не будет срабатывать. Дальше подбирайте: `0.5` — как
в манифесте, `0.6–0.7` — строже (меньше ложных), `window` 5–6 —
устойчивее, 3–4 — быстрее.

### Как добавить свою модель

1. Положите в `models/` два файла с одинаковым именем:
   `моё_слово.json` и `моё_слово.tflite` (микрофон 16 кГц, моно;
   формат microWakeWord v2).
2. Манифест — обычный JSON:

   ```json
   {
     "type": "micro",
     "wake_word": "Моё слово",
     "model": "./моё_слово.tflite",
     "version": 2,
     "micro": {
       "probability_cutoff": 0.5,
       "feature_step_size": 10,
       "sliding_window_size": 5,
       "tensor_arena_size": 32000
     }
   }
   ```

3. Проверьте поля: `type=micro`, `version=2`, `model` — путь к
   `.tflite` относительно манифеста (`./` допустим), `wake_word` —
   подпись, `micro` — порог, шаг признаков (10 мс), окно и размер
   арены из модели.
4. Права — `644`, владелец `root`: файлы читает агент.
5. Укажите новый манифест в `[ww] model`, поправьте `threshold`/
   `window` и перезапустите агента.

Имена файлов могут быть кириллицей (файловая система UTF-8), но без
пробелов и слэшей; имя в `model` должно совпадать с файлом. Если
манифест ссылается на отсутствующий `.tflite`, `Manifest.load`
выдаст ошибку ещё до запуска.

Проверить модель без платы можно через `feed()` на записи фразы:

```python
ww = WakeWord(engine="microwakeword",
              model="models/алиса.json")
event = ww.feed(pcm)          # куски s16le, моно, 16 кГц
print(event and event["word"])
```

## На колонке

В агенте `micro_ww` запускается через `[ww]` в `a_settings.ini`.
Пример текущей настройки на плате:

```ini
[ww]
model=/home/microp/micro_ww/models/hey_jarvis.json
threshold=0.85
window=3
cooldown_ms=1000
```

Порог и окно здесь переопределяют манифест (0.97 и 5) — иначе на
живой речи срабатывания редкие. После правки нужен перезапуск агента.

## Ограничения

- только 16 кГц моно `s16le`; другие частоты не поддерживаются;
- модель `hey_jarvis` — английская фраза; своё слово потребует новой
  модели и манифеста;
- потоков нет: один `poll()` — один шаг, `listen()` блокирует цикл;
- микрофон один: `micro_ww` и ASR работают по очереди, во время
  прослушивания микрофон занят;
- состояние потока живёт в C-рантайме; `reset()` нужен, если после
  срабатывания продолжаете тем же объектом;
- инференс должен укладываться в шаг 10 мс; на слабой нагрузке это
  отдельный риск (замер на длинном прогоне — в планах);
- ложное срабатывание и тишина — не ошибки: это просто отсутствие
  события.

## Тесты

На хосте, без платы:

```sh
_venv/bin/python -m unittest discover \
    -s micro_p_libs/micro_ww/tests -p 'test_*.py'
```

Проверяются манифест, окно и порог, `WakeWord` (`poll`/`listen`/
`feed`/`reset`/`stop`), `fake`-движок, микрофон с подменой
`micro_hal`, C-рантайм через `ctypes` и фикстура `hey_jarvis.pcm`.

Тесты C-рантайма требуют собранной `_tmp/libc_ww_host.so`
(`csrc/build-host.sh`); без неё они пропускаются.

Текущий результат: **134 OK** (с собранной host-библиотекой).
